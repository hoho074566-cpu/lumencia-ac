LUMENSIA V1.5.6 — NPC Goal V2 implementation task

Goal: evolve V1.5.5 active_goal from passive persistence into evidence-based multi-turn progression, lifecycle transitions, replacement history, and debug visibility without adding another model call.

Required behavior:
1. Keep exactly one canonical core/model call per turn.
2. Extend the existing npc_state_updates structured output with nullable goal fields: goal_progress_delta (-100..100), goal_state (active|blocked|completed|abandoned), goal_reason, goal_next_action, and goal_replace (boolean). current_goal remains the canonical display/desire text and backward-compatible field.
3. Emit goal changes only when the turn provides real evidence. Never advance goals just because an NPC spoke or appeared. A non-zero goal_progress_delta must have a non-empty goal_reason; otherwise runtime ignores the delta. State transitions must likewise have a non-empty goal_reason.
4. Goal identity is NOT derived from exact generated text. If an existing goal is present and goal_replace is false/null, a rephrased current_goal updates the desire text but keeps the same runtime goal id, progress, priority, urgency and source_turn. Only goal_replace=true (or no prior goal exists) starts a new goal identity.
5. Same goal: apply bounded progress delta and preserve lifecycle. Clamp progress 0..100. blocked preserves progress unless a real delta is supplied. completed => 100. abandoned preserves final progress.
6. Reopen rules: blocked->active is allowed with an explicit goal_state=active plus non-empty goal_reason. abandoned->active is allowed with explicit goal_state=active plus non-empty reason and preserves its prior progress unless a real delta is supplied. completed->active is allowed ONLY when goal_state=active, goal_reason is non-empty, and goal_progress_delta is strictly negative so resulting progress is below 100; otherwise it remains completed at 100.
7. Replacement: goal_replace=true archives the prior goal into npcInnerStates.goal_history (max 6) with id/desire/final_state/final_progress/ended_turn/end_reason, then creates the new active goal at progress 0 plus only a valid explicitly reported first-turn delta. New goals never inherit prior progress/priority/urgency/source_turn.
8. Preserve reasons/next_actions as bounded recent evidence. Add last_progress_delta, last_progress_reason, updated_turn. Keep source_turn as goal start turn. goal_next_action may update next_actions only when non-empty.
9. Event Director may read active goals only after all existing eligibility guards. Goal V2 must not bypass direct-focus, physical location, schedule, participant, callback, surprise cooldown, or no-event guards. Blocked/completed/abandoned goals must not create or weight Director eligibility.
10. Relationship Reason V1 remains unchanged and one-call architecture remains unchanged.
11. DEBUG should show goal P/U/state/progress plus latest delta/reason and recent goal history.
12. Version target: app 1.5.6, API adapter 0.8.2. Stable paths remain /app-runtime.js, /api/chat-router, /api/lib/context-router.js, /api/chat. No versioned duplicate runtime/API files.
13. Preserve HF1 context budgets and prompt caching behavior.
14. Add focused regression tests covering: +progress with reason, invalid delta without reason ignored, negative setback clamp, blocked preservation, completion=100, abandonment, blocked reopen, completed reopen without delta rejected, completed reopen with negative delta accepted, rephrased same goal preserves identity/progress, explicit goal_replace resets metadata/progress, goal_history cap, no progress from mere dialogue, one canonical coreHandler call site, stable paths and version/debug markers.
15. Protected core/runtime change: do not auto-merge. Require Safety + Vercel + exact-current-HEAD Codex review P0/P1=0 + no conflict + current-main revalidation before manual merge.

This document is the implementation contract and may remain as release documentation.
